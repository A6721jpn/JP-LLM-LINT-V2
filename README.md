# JP-LLM-LINT-V2

Codexの回答を意味グラフに変換し、Geminiが構成から作文し直す。その「意味グラフ → 完成文」を、Qwenの学習用教師データにする独立プロジェクト。

**現在は仕様文書のみ。ログ取込・外部送信・教師生成・学習は未実施。** 旧JP-LLM-LINTのコード、Guard、評価結果、教師セットには依存せず、変更もしない。

## 1. 役割と工程

```text
対象会話の選定・学習／検証分割
  → Codexによる意味グラフ抽出
  → Geminiによる抽出検査（原文とグラフ）
  → 別呼出しのGeminiによる作文（グラフだけ）
  → 別呼出しのGeminiによる意味・品質検査（原文、グラフ、完成文）
  → 機械検査・採否記録
  → 合格したグラフと完成文を教師化
```

- 一件はCodexの回答全体。段落単位には分割しない。
- 抽出に使うのは対象回答と、その時点までの必要な会話文脈。後続会話の結果を過去の回答へ混入させない。文脈は指示対象や目的の解決に使い、対象回答にない主張を追加しない。
- 元の著者セッションによる抽出と、別Codexへのログ再提示による抽出を区別して記録する。後者を「著者の記憶」と扱わない。
- Codexは内容と意味上の関係を決める。段落、見出し、説明順、箇条書きなどの文章構成は指定しない。ユーザーが明示した形式制約だけ保持する。
- 抽出検査後にグラフを固定する。完成文を通すために内容や重要度を変更しない。
- 作文担当には原文、会話ログ、原文の見出し・文順・根拠位置、検査結果を渡さない。指示は外部の[教師生成プロンプト](prompts/teacher_generation.md)を使う。
- Geminiの生成・検査はEffort HIGH。別呼出しでも独立したモデルによる検証ではないため、人手の抜き取り確認を併用する。

## 2. 最小データ契約

作文入力は、以下の6キーを持つJSONオブジェクトとする。版は `meaning-graph-v1`。

| キー | 内容 |
|---|---|
| `version` | `meaning-graph-v1` |
| `task` | 読者、伝達目的、ユーザー指定の形式制約。段落案や説明順は入れない |
| `entities` | 一意なIDと対象名。人物、システム、操作対象など |
| `propositions` | 一意なID、述語と対象、報告／依頼／提案／質問の区別、否定、確実性、時点・完了状態、必須／省略可能／判断不能の区分 |
| `relations` | 命題間の条件、因果、時間順、依存、対比。条件のAND／ORや否定の適用範囲も明示する |
| `assets` | 一意なID、種類、必須か否か、保持方法。数値・単位、コード、表、図、画像などの必要な実データ |

述語・対象名は短く意味の分かる表現とし、元の文章や作文指示を命題へ埋め込まない。命題の配列順は文章の提示順を意味しない。単に `確認` と縮めず、「確認の依頼」「確認済み」「未確認」を区別する。

重要度や意味の対応が判断不能なら抽出検査で保留する。グラフを小さくするために必要な意味を捨てない。

### 表・図・コード

- 表は値と行・列見出しの対応、単位、注記を保持する。表形式自体が必要かは、ユーザー指定や比較目的から判断する。
- 図は接続、方向、分岐条件などを意味として保持する。配置・色・線種は意味を担う場合だけ制約にする。
- そのまま保持するコード・画像等は、作文中で `[[asset:ID]]` として参照し、ホストが原物を復元する。必須素材は一回参照し、未知ID・重複参照・必須参照の欠落を拒否する。
- 画像の意味を読み取れない場合は推測しない。原物の保持だけで要件を満たさなければ保留する。図の新規描画も、検証できる描画経路がない間は教師化しない。

## 3. 教師の採用条件

以下をすべて満たすものだけ採用する。

1. **抽出の正しさ**：結論、依頼、成否、条件、否定、確実性、必要な対象・値を落とさず、原文にない主張も追加していない。
2. **完成文の意味保持**：必須命題と条件を保持し、全主張が原文に支持される。グラフと完成文の一致だけでなく、原文との直接比較も行う。
3. **品質改善**：元回答より読み手の負担が下がり、グラフの逐語訳や不自然な箇条書きになっていない。
4. **機械的整合**：JSON、ID、参照、素材復元、値・単位・コード等に不整合がない。
5. **再構成量**：元回答と素材復元後の完成文の文字変更率が50%以上。`1 - difflib.SequenceMatcher(None, original, output, autojunk=False).ratio()` を使う。全文を対象とし、比較用の空白除去などは行わない。
6. **分割の独立性**：検証・評価用会話と、その重複・近似重複が学習側に混入していない。

50%は教師採用の条件であり、品質の点数でも実運用の書換え義務でもない。率を稼ぐだけの改変、良い原文の無理な書換えは不採用。失敗候補を通すための条件緩和・無制限再生成は行わない。不合格・判断不能も母数から消さず保存する。

## 4. 保存と最初の確認

- **監査用**：元会話・回答ID、必要な文脈参照、原文、グラフ、原文との根拠対応、省略項目と理由、作文本文と素材復元後の完成文、検査結果、不採用理由、モデル・プロンプト・スキーマの版とhash。
- **学習用**：固定指示＋意味グラフ＋必要素材を入力、採用した作文応答の `text` を正解とする。素材参照トークンは保持し、復元は実運用でもホストが行う。管理用JSON、判定コメント、原文の文章部分・根拠位置は学習入力へ混ぜない。
- 分割は生成前に会話単位で固定する。元ログ・教師本文・画像・認証情報はローカルの非公開領域に保存し、Gitや外部公開先へ載せない。
- 外部送信は処理対象として許可されたデータだけ。Codexは抽出に必要な入力、Geminiは担当工程に必要な入力に限定する。実行環境のデータ取扱規則と矛盾する場合は送信前に停止する。
- 最初は報告・依頼・提案・条件付き説明・コード／表混在を含む**50件程度の候補**で確認する。採用数を50件に合わせない。抽出欠落、意味変更、品質、判断不能、採用率を別々に記録する。
- 少量確認後にスキーマとプロンプトを固定して本生成へ進む。実装・検証前の品質や性能を、達成済みとは記録しない。
